## Pistes et choix faits
- `schema.py` vérifie tout ce qui ne dépend que du YAML (plafonds, références croisées, axes balayables, `{placeholders}` des questions). Les erreurs de cohérence sortent en `SpecIssues` (chemin par erreur) : le chargeur en tire le numéro de ligne via `yaml.compose`.
- Mesure : `texts` est facultatif même avec cible (`alpha` de Student n'en a pas) ; target, direction, ok_within et broken_beyond vont ensemble.
- `law` d'une option reste une chaîne libre : le registre appartient à R2 (`laws.py`). Idem pour `call` des méthodes et les types de vues.
- À faire côté `expr.py` : noms des expressions, cycles entre variables. À brancher avec R2 : chaque `bind` de vue contre `provides` (`method_contract.py`).
- Les champs YAML `from` s'appellent `from_` en Python : utiliser `model_dump(by_alias=True)` pour servir `GET /api/experiments/{id}`.
- Environnement : `uv` absent du PATH, Python système 3.14 (le projet veut 3.12). Tests lancés dans un venv temporaire.
- Écarts de `contracts.py` avec le cahier, à valider avec Kilian (R3) avant le gel :
  - `TrainingSessionResponse` : requête en POST `{filter, count, seed?}` (CLAUDE.md), `stale_link` gardé à `false` par défaut (réservé au lien avec `h=`, P1).
  - `SweepResult.target` : nombre, ou dictionnaire par méthode quand la cible est `base` (cas Student : puissance de chaque méthode vs sa propre Référence). `MeasureResult.target` vaut `"base"` et la cible se lit dans `baseline`.
  - `ViewResult.data` : `{series: [Series], ...}` avec champs supplémentaires libres ; le contenu par type de vue (annexe E) reste à figer par les fixtures.
  - `SweepRequest` n'a pas de `raw_content` (cahier) : un YAML importé ne peut pas être balayé, à voir si l'Import (P1) en a besoin.
  - `Series.role` = les 8 rôles de style de `roles.ts` ; `MethodInfo.role` = method / correction / alternative.
- Contrats alignés sur `frontend/src/lib/views.ts` (R3) : `ViewResult.series` à plat, `Series` avec `slot`, `x`, `y`, `low`, `high`, `hit`, `value` ; rôle `data` ajouté ; `ViewResult.mode`, `axes {x, y}`. Ajout de `Series.paths` (trajectoires, P1) : seul champ ajouté sans demande de R3. Vue `sensitivity` : `series` vide, l'interface appelle `/api/sweep`.
- Constat pour R2 (fixtures, graine 42, 500 répétitions, n = 25, Cauchy) : puissance de Wilcoxon 39 % contre 66 % à l'état sain, soit une perte de 0,27 : Wilcoxon est Rompu avec `broken_beyond: 0.25`. Le CLAUDE.md prévoit de passer à `0.30` au-delà de 0,22.
