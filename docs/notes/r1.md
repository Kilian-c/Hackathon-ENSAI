### Règles d'écriture des YAML pour le moteur actuel (à suivre dès maintenant)
1. **Grille déterministe** : `repeat: 1`, `n` ≤ 5000, `x` construit avec `idx` (point milieu : `(idx + 0.5) / n`). Un intervalle [a, b] : `a + (b - a) * (idx + 0.5) / n`, et l'intégrale vaut alors `(b - a) * mean(f, axis=1)`. Un intervalle infini se tronque (le dire dans le texte).
2. **Exposants bornés à 100** dans les expressions : écrire `exp(p.k * log(x))` au lieu de `x ** p.k` pour de grands k (prototype : `x ** 1000` est refusé).
3. **Résolution** : une bosse de largeur 1/k doit contenir plusieurs points de la grille : garder k ≤ n / 10 dans `sweep_values`.
4. **Pas de bruit Monte Carlo** avec `repeat: 1` : les seuils `ok_within` / `broken_beyond` sont exacts (les erreurs Monte Carlo valent `null`, les « seuils proposés » de `/api/validate` ne s'affichent pas : c'est normal).
5. **Hypothèses non simulables** (mesurabilité : une fonction non mesurable ne se construit pas numériquement) : ne pas en faire une hypothèse cassable ; l'écrire dans `theorem.statement` en attendant l'étape 2 ci-dessous.
6. **Vues** : `curves` avec `bind: { t: gen.x, series: [ { y: gen.f, label: "f_k" } ] }` dessine f_k ; `sensitivity` sur `p.k` montre la suite des intégrales. Limite actuelle : une courbe lue dans le générateur (`gen.*`) n'a pas de Référence (état sain) superposée (étape 3).
7. **Le reste ne change pas** : 3 questions au moins (`verify` vérifié à 90 % sur 50 tirages, test 6), `why` et `when_broken` partout, `{value}` dans les textes de mesure, contre-exemples qui rompent une mesure (test 4), état sain Fiable (test 1).

## GUIDE : écrire les YAML des théorèmes d'intégration (à relire avant de générer les YAML à partir du cours)

**Contexte** : R1 donnera le cours (théorèmes d'intégration de 1re année ENSAI : mesurabilité, intégrabilité, dérivabilité…) et demandera de générer les YAML. Ce guide rassemble tout ce qu'il faut savoir. Branche de travail : `r1/integration`. Plan et étapes : section « Plan : nouvelle catégorie Intégration » plus bas.

### 1. Démarche pour chaque théorème (dans cet ordre)
1. **Choisir ce que l'on casse** : une hypothèse du théorème qui se **simule** (domination, uniformité de la convergence, continuité ou dérivabilité de f, intégrabilité de la limite, positivité, support borné, signe). Écrire ce qu'elle garantit (`why`) et ce que l'on voit quand elle tombe (`when_broken`).
2. **Choisir la mesure** (une seule `primary: true`) : l'écart entre les deux membres de la conclusion (par exemple `|lim ∫ f_n − ∫ lim f_n|`), ou l'écart à une valeur exacte connue. Verdict Fiable quand le théorème tient, Rompu quand l'hypothèse tombe.
3. **Trouver un contre-exemple classique** (celui du cours : bosse glissante `k·1[0,1/k]`, `x^k` sur [0,1], `sin(nx)/n`, fonction de Dirichlet, `1/x` sur ]0,1], `sin x / x` sur ℝ…) : c'est l'état cassé, et la matière des `counterexamples`.
4. **Simuler avant d'écrire les seuils** (règle de R2) : lancer `runner.run` sur l'état sain et sur chaque état cassé, relever les écarts, poser `ok_within` et `broken_beyond` avec de la marge (si l'écart est exact, la marge est facile : pas de bruit).
5. Écrire le YAML, le valider : `uv run python scripts/new_experiment.py --check <fichier>` (erreurs par ligne, tests 1, 3, 4, 10), puis `uv run pytest -q tests/test_experiments.py tests/test_p1_content.py` (déposer le fichier dans `experiments/`), puis `CRASHTEST_DRAWS=50 uv run pytest -q tests/test_experiments.py -k "test_6 and <id>"`.
6. Créer le brouillon avec `uv run python scripts/new_experiment.py statistique <id> --title "…" --discipline intégration --level 2` puis remplacer son contenu (copie fonctionnelle de `moyenne_mediane`), ou partir du prototype du test `tests/test_quadrature.py` (constante `YAML`).

### 2. Champs obligatoires et règles de forme (vérifiées par le chargeur et les tests)
- **Premier niveau** : `schema_version: 1`, `id` (minuscules, chiffres, `-`, `_`), `title`, `discipline: "intégration"` (identifiant court `integration`, la pastille de l'Entraînement apparaît seule), `level: "1" | "2" | "3"` (chaînes), `concepts`, `theorem {name, statement}`, `equation {tex, terms}`, `params`, `hypotheses`, `counterexamples`, `generator`, `methods`, `measures`, `challenges`, `auto_sweep`, `views`, `questions`. Aucune autre clé (`extra="forbid"`).
- **Texte** : tout entre guillemets ; **français, vouvoiement** (le test refuse « tu, ton, ta, tes, toi ») ; aucun chiffre écrit en dur dans les textes de mesure : utiliser `{value}`.
- **Hypothèse** (`hypotheses.<id>`) : `type` (`continuous` avec `range` et `step`, `choice` avec `options`, `boolean`), `healthy_value`, `label`, `category`, `statement_tex` (LaTeX sans dollars), **`why` et `when_broken` obligatoires** (test 10), `affects: [termes de l'équation]`, facultatifs `ok_label`, `broken_label`, `robust_expected`, `disabled_when`, `disabled_text`. Une option de `choice` porte `label` et `expr:` (expression libre, la fonction de l'état) ou `law:`.
- **Équation** : `equation.tex` avec des `{{terme}}` ; `terms.<terme>.ok` (et `corrected` facultatif) en LaTeX ; chaque hypothèse cite dans `affects` les termes qu'elle met en cause (ils passent au rouge quand elle tombe).
- **Méthodes** : exactement 1 `role: method`, au plus 1 `correction`, au plus 2 `alternative`, 4 au plus ; une correction ou une alternative a un `explain` ; `repairs: [hypothèses]` pour la correction (test 3 : elle ramène à Fiable ou Fragile ces hypothèses cassées).
- **Mesures** : `agg`, `label`, `decimals` (0 à 6), une seule `primary: true`, `target` (nombre ou `base`), `direction` (`below`, `above`, `both`), `ok_within`, `broken_beyond`, `texts {ok, warning, broken}`.
- **Contre-exemples** : `id`, `label`, `explain`, `state` ; chacun doit rompre au moins une mesure (test 4).
- **Défis** : `id`, `goal`, `when` (expression), `unlock` ; atteignables par un balayage (test 5 : l'état est cherché sur une grille de valeurs des hypothèses et paramètres).
- **Questions** : au moins 3, dont au moins 2 de type `misconception` ou `diagnostic_auto` (test). `misconception` : `prompt`, `hypothesis`, `choices` (exactement un `correct: true`), chaque choix a `reveal_state`, `verify` (condition vraie sur 90 % de 50 tirages, test 6), `focus_view`, `explain`, `procedural_params` facultatif (`{n}` dans l'énoncé). `diagnostic_auto` : `view` et `pathologies: { from: [hyp, hyp.option] }`. `prediction` : `state`, `sweep { target, from, to }`, `measure`, `procedural_params`.
- **Plafonds** : YAML 64 Ko, expression 300 caractères, `repeat` ≤ 1000, `n` ≤ 5000, 4 méthodes, 30 variables ; **exposants ≤ 100** dans les expressions.

### 3. Modèle de calcul pour une intégrale (testé sur le vrai moteur)
- **Générateur** : `type: random`, `repeat: 1` (calcul déterministe, pas de bruit Monte Carlo), `n: 2000` (jusqu'à 5000), `x: { expr: "(idx + 0.5) / 2000" }` (milieux de cellules sur [0, 1]) ; sur [a, b] : `a + (b - a) * (idx + 0.5) / n`. La fonction est une variable : `f: { expr: "@h.famille" }` (l'option choisie de l'hypothèse `famille`, chaque option est une expression de `x` et de `p.k`). Les opérateurs `//` et `%`, `where`, `exp`, `log`, `sin`, `cos`, `abs`, `sign`, `floor`, `clip`, `minimum`, `maximum`, `cumsum`, `sort`, `quantile` existent ; `idx` est l'indice d'observation ; une comparaison `(x < 1 / p.k)` vaut 0 ou 1.
- **Méthode d'intégration** (voir `backend/methods/quadrature.py`) : `call: quadrature`, `args: { x: x, f: f, a: 0, b: 1, kind: "rectangles" | "trapezes" | "simpson" | "monte_carlo", truth: <valeur exacte>, samples: 200 }` ; `reps : est, error` ; `example : x, f`. `truth` peut être une expression (`"p.k ..."`, `"1 / (p.k + 1)"`). Pour comparer des règles : méthode principale `rectangles`, alternative `simpson`, etc.
- **Sans `quadrature`** (plus simple, un seul calcul) : `call: formula_estimate`, `args: { est: "mean(f, axis=1)", truth: … }` (somme de Riemann sur [0, 1]). Pour un autre intervalle : `(b - a) * mean(f, axis=1)`. Pour une somme de deux termes : une expression dans `est`.
- **Intégrer une suite** : le rang `k` est un paramètre (`params.k` avec `sweep_values: [1, 10, 100, 1000]` pour la vue Sensibilité). **Résolution** : garder `k ≤ n / 10` (une bosse de largeur 1/k doit contenir plusieurs points). **Exposants** : `x ** p.k` est refusé pour k > 100, écrire `exp(p.k * log(x))`.
- **Vues utiles** : `curves` avec `bind: { t: example.x, series: [ { y: example.f, label: "f_k" } ] }` (la **Référence** saine se superpose seulement si la courbe est lue dans `example` ou `curves`, d'où `quadrature`) ; `sensitivity` avec `sweep: { axes: [p.k] }` (suite des intégrales selon k) ou `[h.famille]` (une barre par option) ; `validity_domain` avec `sweep: { axes: [h.famille, p.k] }` ; `distribution` seulement avec `repeat` > 1 (inutile ici). Après l'étape 4 : `ui: { fill_area: true }` remplit l'aire sous la courbe.
- **Mesure en logarithme** (erreurs très petites) : `agg: "mean(log10(abs(reps.error) + 1e-16))"` ; `label: "log₁₀ de l'erreur …"`, `texts: "… 10^{value} …"` (l'interface rend l'exposant), thresholds en échelle log. Sinon rester en erreur absolue ou relative.

### 4. Formules et notation
- **Dans l'énoncé du théorème, `why`, `when_broken`, `explain` des cas limites, énoncés et choix du QCM** : `$f_n \to f$` en ligne, `$$\lim_n \int f_n \, d\mu = \int f \, d\mu$$` centrée, `\$` pour un vrai dollar. KaTeX mode sûr ; formule invalide en rouge.
- **Ne pas mettre `$` dans** : libellés de mesure, titres d'axes, noms de méthodes, libellés de défis (affichés par Plotly ou hors du rendu) → Unicode (`λ₁`, `σ²`, `∫`, `μ`, `ε`, `→`, `≤`, `∞`, `Σ`, `L¹`, `‖f‖`…).
- **`statement_tex` d'une hypothèse et `equation.tex`** : LaTeX pur, **sans dollars**.
- Pas de virgule ou de point-virgule collé à un nombre décimal dans un énoncé de QCM (`{r}` en fin de phrase, pas avant une virgule).

### 5. Idées de théorèmes, de familles de fonctions et d'états cassés (à adapter au cours reçu)
- **Convergence dominée** : f_k = x^k (dominée) contre f_k = k·1[0,1/k] (non dominée : l'intégrale vaut 1 alors que la limite vaut 0). Mesure : `|∫ f_k − ∫ lim f_k|`.
- **Convergence monotone** : suite croissante contre suite non monotone ; **Fatou** : inégalité stricte avec la bosse glissante.
- **Continuité sous le signe ∫** : F(t) = ∫ f(x, t) dx, hypothèse de domination uniforme en t, contre-exemple avec pic qui dépend de t.
- **Dérivation sous le signe ∫** : comparer F'(t) calculée par différence finie (`quadrature` sur f(x, t+h) et f(x, t−h)) et ∫ ∂ₜf (méthode principale) ; hypothèse : ∂ₜf dominée.
- **Fubini-Tonelli** : intégrale double sur une grille m × m (`n = m * m`, `i = idx // m`, `j = idx % m`), les deux intégrales itérées ; contre-exemple classique `(x² − y²)/(x² + y²)²` (intégrales itérées différentes, f non intégrable) → étape 5 du plan (méthode `iterated_integrals`).
- **Intégrabilité / Riemann contre Lebesgue** : `sin x / x` (Riemann impropre mais pas Lebesgue) tronquée sur [0, T] avec T croissant ; fonction de Dirichlet (Lebesgue 0, Riemann impossible : la somme de Riemann dépend de la grille).
- **Mesurabilité** : ne se simule pas. L'écrire dans `theorem.statement` et dans une hypothèse non cassable (étape 2 du plan : `disabled_when` + `disabled_text`, ou hypothèse `robust_expected`).
- **Changement de variable, intégrale de Gauss, inégalités (Markov, Jensen)** : les intégrales exactes sont connues, utiles pour `truth`.

### 6. Pièges rencontrés dans le projet (à ne pas refaire)
- Une courbe lue dans le générateur (`gen.f`) n'a pas de Référence ; lire dans `example` (méthode `quadrature`).
- Pas de bruit avec `repeat: 1` : `mc_se` est `null`, les « seuils proposés » de `/api/validate` ne s'affichent pas (normal) ; un verdict ne dépend que de la grille.
- Un identifiant de série contenant un `.` casse la barre de couleur de Plotly (rien à faire ici sauf pour une vue `heatmap` : l'échelle passe par `layout.coloraxis`).
- Mesure sans cible (`target` absent) : informative, pas de verdict ; elle ne peut pas être `primary`.
- Ne pas changer un seuil sans resimuler ; noter les marges fines (< 0,03) dans la passation.
- Après tout ajout de méthode : `uv run python scripts/gen_catalog.py` et un exemple dans `_SAMPLE_CALLS` (`tests/test_method_contract.py`).
- Le QCM et l'Entraînement tirent au plus **une** `misconception` par expérience et par série ; avec 3 questions par expérience, la série « Intégration » aura 9 à 12 emplacements.

## Bug des graduations de la matrice qui s'empilent (H15)
- **Symptôme** (remonté par R1) : dans la vue des matrices (ex. « La matrice A du premier système »), à chaque mise à jour, un jeu de graduations s'ajoute à droite de la barre de couleur ; la marge droite grandit et les cartes sont écrasées.
- **Cause** (prouvée dans un vrai navigateur, 103 graduations et 618 px de large dans une page de test) : une barre de couleur attachée à une trace prend pour identifiant `cb<uid>`, avec `uid` = id de la série (`matrice.matrix.jacobi`) ; Plotly retrouve ses graduations par un sélecteur CSS où chaque point est un séparateur de classes, donc il n'efface jamais les anciennes. Touche toute vue `heatmap` dont l'id de série contient un point.
- **Correction** (`plot.ts`, `heatmapFigure`) : l'échelle commune passe par `layout.coloraxis` (`cmin`, `cmax`, `colorscale`, `colorbar`) ; les traces portent `coloraxis: 'coloraxis'`. Test de non-régression dans `plot.test.ts`. Vérifié au navigateur sur les 4 expériences à matrice : 1 barre, pas de doublon, largeur stable.
- **À savoir** : un navigateur sans interface est installable hors du projet (Playwright, dossier temporaire) et sert à vérifier l'écran ; ne jamais mettre de barre de couleur sur une trace dont l'uid contient un point.

## Pistes et choix faits (toujours valables)
- `schema.py` vérifie tout ce qui ne dépend que du YAML (plafonds, références croisées, axes balayables, `{placeholders}` des questions). Les erreurs de cohérence sortent en `SpecIssues` (chemin par erreur) : le chargeur en tire le numéro de ligne via `yaml.compose`.
- Mesure : `texts` est facultatif même avec cible ; target, direction, ok_within et broken_beyond vont ensemble.
- `law` d'une option reste une chaîne libre : le registre appartient à R2 (`laws.py`). Idem pour `call` des méthodes et les types de vues.
- Les champs YAML `from` s'appellent `from_` en Python : utiliser `model_dump(by_alias=True)` pour servir `GET /api/experiments/{id}`.
- Environnement : `uv` absent du PATH, Python système 3.14 (le projet veut 3.12). Tests lancés dans un venv temporaire.
- Écarts de `contracts.py` avec le cahier, à valider avec Kilian (R3) :
  - `TrainingSessionResponse` : requête en POST `{filter, count, seed?}`, `stale_link` à `false` par défaut (réservé au lien avec `h=`, P1).
  - `SweepResult.target` : nombre, ou dictionnaire par méthode quand la cible est `base`. `MeasureResult.target` vaut `"base"` et la cible se lit dans `baseline`.
  - `ViewResult.data` : `{series: [Series], ...}` avec champs supplémentaires libres.
  - `SweepRequest` n'a pas de `raw_content` : un YAML importé ne peut pas être balayé (à voir si l'Import en a besoin).
  - `Series.role` = les 8 rôles de style de `roles.ts` ; `MethodInfo.role` = method / correction / alternative.
- Contrats alignés sur `frontend/src/lib/views.ts` : `ViewResult.series` à plat, `Series` avec `slot`, `x`, `y`, `low`, `high`, `hit`, `value`, `paths` ; rôle `data` ajouté. Vue `sensitivity` : `series` vide, l'interface appelle `/api/sweep`.
- `expr.py` : évaluateur maison sur `ast` (liste blanche de noeuds), pas `asteval` : exposants bornés à 100, espaces de noms en dictionnaires sans accès aux attributs Python.
- `@h.<id>` : l'appelant fournit `Env.option(id)`. `law`, `normal`, `uniform`, `bernoulli` sont fournies par le générateur (elles dépendent du flux aléatoire) ; `ar1` et `ols_match` sont dans `BASE_FUNCTIONS`.
- `m.<mesure>` seul = valeur de la méthode principale ; `m.<mesure>.<methode>` ; `m.<mesure>_se`.
- Arguments de méthodes : une chaîne est une expression si elle se lit et que ses noms existent, sinon un texte littéral. Une variable mal écrite devient donc un texte et échoue dans la méthode.
- `resolve_state` refuse (StateError, en français) un paramètre ou une hypothèse inconnus, hors bornes, ou du mauvais type ; arrondit les hypothèses continues au `step`. `healthy()` donne l'état de la Référence.
- `generate()` : un flux par variable (`rng_for(seed, nom)`), donc Référence et état courant partagent les aléas ; les points ajoutés agrandissent seulement les variables de `inject`, après le calcul. `dims: obs_p` refusé (P2).
